默认情况下，[Agent](/feat/ai/agent/) 每次调用都是独立的——它不记得上一轮你说过什么。`Memory` 机制让 Agent 具备跨轮次的记忆能力：自动存下交互历史，并在后续调用时检索相关记忆注入上下文。

## 最小用法：内存记忆

```java title="MemoryDemo.java"
import tech.smartboot.feat.ai.FeatAI;
import tech.smartboot.feat.ai.agent.FeatAgent;

public class MemoryDemo {
    public static void main(String[] args) throws Exception {
        FeatAgent agent = FeatAI.agent(opts -> {
            opts.chatOptions().model(/* 你的模型配置 */);
            // 启用内存记忆
            opts.memory(memoryOpts -> memoryOpts
                    .maxMessages(100));       // 每个会话最多保留 100 条
            opts.memoryTopK(5);               // Agent 每次检索 5 条注入上下文
            opts.sessionId("user-session-123");
        });

        agent.execute("你好，我是张三").get();
        agent.execute("请问我叫什么名字？").get();  // Agent 能答上来
    }
}
```

三件事各自的作用：

- `opts.memory(...)`：启用记忆并配置存储策略，例如每个会话的消息上限
- `opts.sessionId(...)`：给本次 Agent 调用标记会话 ID；向量记忆会用它执行会话过滤
- `opts.memoryTopK(n)`：控制 Agent 每次检索多少条历史记忆注入提示词
- `MemoryOptions.defaultTopK(...)`：只影响直接调用 `Memory.search(query)` 时的默认数量，不替代 Agent 的 `memoryTopK`

内存实现（`InMemoryMemory`）数据存在 JVM 里，**重启即失**，适合开发测试和单机会话场景。

## 记忆的工作机制

理解这两点，可以避免对记忆系统的误解：

1. **检索是按相关性注入，不是全量回放**。每次调用 Agent 时，会用当前输入检索最相关的 topK 条历史记忆注入上下文——`maxMessages` 只是每个会话的存储上限，不是上下文长度。
2. **不要把当前的 InMemoryMemory 当作多用户隔离边界**。它按 sessionId 分桶存储，但当前 `search()` / `getRecent()` 会遍历所有会话桶，未按当前用户过滤。多用户场景不要依赖它隔离不同用户的数据。
3. **VectorMemory 需要显式设置 sessionId**。默认开启 `sessionIsolation`，检索会按配置的 sessionId 过滤；Agent 示例应通过 `opts.sessionId(...)` 设置同一个会话标识。

其他常用配置：

| 配置 | 默认值 | 说明 |
|---|---|---|
| `similarityThreshold` | 0.5 | 相似度低于阈值的记忆不参与检索 |
| `sessionIsolation` | true | VectorMemory 默认按 sessionId 过滤；InMemoryMemory 当前检索实现尚未应用此过滤 |
| `enableDeduplication` | false | 合并内容高度相似的消息（阈值 0.95） |
| `importanceThreshold` | 0.0 | 按消息重要性过滤，低价值记忆不检索 |
| `includeThoughts` | false | 是否把 Agent 的思考过程也存入记忆 |

## 长期记忆：向量记忆

内存记忆按时间窗口保留，适合"本次会话内记得住"。要让 Agent 跨会话长期记住用户偏好、历史结论，用向量记忆——它把记忆交给向量库，检索按语义相似度进行：

```java title="VectorMemoryDemo.java"
import tech.smartboot.feat.ai.FeatAI;
import tech.smartboot.feat.ai.agent.FeatAgent;
import tech.smartboot.feat.ai.agent.memory.Memory;
import tech.smartboot.feat.ai.vector.ChromaVectorOptions;
import tech.smartboot.feat.ai.vector.ChromaVectorStore;

public class VectorMemoryDemo {
    public static void main(String[] args) {
        FeatAgent agent = FeatAI.agent(opts -> {
            opts.chatOptions().model(/* 你的模型配置 */);
            opts.memory(Memory.vector(vectorOpts -> {
                vectorOpts.vectorStore(new ChromaVectorStore(new ChromaVectorOptions()
                        .setUrl("http://localhost:8000")));
                vectorOpts.embeddingModel(/* EmbeddingModel 实例，见 Embedding 章节 */);
                vectorOpts.collectionName("agent_memory");
            }));
            opts.memoryTopK(5);
            opts.sessionId("user-session-123");
        });
        // ...
    }
}
```

向量记忆需要两个外部依赖：一个 **EmbeddingModel**（把文本转向量，见 [Embedding](/feat/ai/embedding/)）和一个 **VectorStore**。内置支持 Chroma 和 Milvus（`ChromaVectorStore` / `MilvusVectorStore`）。

<Aside type="caution">
向量记忆示例必须设置稳定的 `sessionId`。当前 `VectorMemory` 写入时会为未设置的消息填充默认会话标识，但检索过滤使用配置中的 sessionId；不设置会话 ID 时，写入与检索条件可能不一致。另请确认向量库集合维度与 Embedding 模型实际输出维度一致。
</Aside>

选型时先确认数据隔离和持久化需求：内存记忆适合单用户开发验证；需要多用户隔离和跨实例共享时，应使用经过验证的外部向量存储，并显式配置 sessionId。

## 直接操作 Memory API

不经过 Agent 也可以独立使用记忆存取：

```java title="MemoryApiDemo.java"
import tech.smartboot.feat.ai.agent.memory.Memory;
import tech.smartboot.feat.ai.agent.memory.MemoryMessage;

import java.util.List;

String sessionId = "user-session-123";
Memory memory = Memory.inMemory(opts -> opts.maxMessages(50));

MemoryMessage userMessage = MemoryMessage.ofUser("用户喜欢简洁的回答");
userMessage.setSessionId(sessionId);
memory.add(userMessage);

MemoryMessage assistantMessage = MemoryMessage.ofAssistant("好的，已记住");
assistantMessage.setSessionId(sessionId);
memory.add(assistantMessage);

// 按相关性检索
List<MemoryMessage> related = memory.search("回答风格", 3);
// 取最近 N 条
List<MemoryMessage> recent = memory.getRecent(5);
// 只清除指定会话
memory.clear(sessionId);
```

适合把记忆能力嵌入自己的编排逻辑，而不是完全交给 ReAct 循环。

## 生产注意事项

- **多实例部署**时，内存记忆各节点独立；此外，当前 InMemoryMemory 的 search/getRecent 会跨 session 桶检索，不适合承担多用户数据隔离。多实例/多用户场景应先修复并验证隔离行为，再使用带显式 sessionId 的外部向量存储
- **隐私合规**：记忆内容是用户交互原文，落地向量库前确认保留策略与用户知情机制
- **删除记忆**：`InMemoryMemory.clear()` 清空全部会话，`clear(sessionId)` 只清理指定会话；当前 `VectorMemory.clear()` 只清理本地缓存，不会清空外部 VectorStore，`clear(sessionId)` 才会尝试删除指定会话的数据。
- **成本控制**：每次调用都会做一次向量检索，记忆规模大时关注向量库的查询延迟
