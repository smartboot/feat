MCP 为 AI 客户端提供了一种调用应用能力的标准方式。客户端可以发现工具、读取提示模板和资源，再按协议调用它们。

在 Feat Cloud 中，MCP 能力通过注解声明。AOT 编译阶段会生成注册代码，应用启动时将这些能力注册到 `McpServer`，不需要运行时扫描注解。

## 先从 Tool 开始

Tool 是最常见的 MCP 能力：把一个业务方法交给模型调用。

```java title="GreetingController.java"
import tech.smartboot.feat.cloud.annotation.Controller;
import tech.smartboot.feat.cloud.annotation.mcp.Param;
import tech.smartboot.feat.cloud.annotation.mcp.Tool;

@Controller
public class GreetingController {

    @Tool(name = "greeting", description = "根据姓名生成问候语")
    public String greeting(
            @Param(required = true, description = "用户姓名") String name) {
        return "你好，" + name + "！";
    }
}
```

这里有两个关键点：

- `@Tool` 声明一个可调用工具，`name` 是客户端调用时使用的名称。
- `@Param` 描述参数名称、是否必填和用途。这些信息会成为工具的输入 Schema，帮助模型判断何时以及如何调用。

**注意：** MCP 的 `@Param` 与 HTTP Controller 的请求参数绑定不是一回事。

## 默认服务与显式端点

Feat Cloud 提供两种组织方式。

### 默认 MCP 服务

如果 Controller 没有标注 `@McpEndpoint`，但其中声明了 MCP 注解方法，且默认服务未被关闭，Feat Cloud 会生成默认 MCP Server。默认 HTTP 端点是 `/mcp`。当前默认服务只启用 Tool；需要暴露 Prompt 或 Resource 时，请使用显式 `@McpEndpoint`。

默认服务默认启用。可以通过 `feat.yml` 关闭：

```yaml title="feat.yml"
server:
  mcp:
    server:
      enable: false
```

默认服务适合快速验证少量 Tool。如果项目需要 Prompt、Resource，或需要划分多个独立的 MCP 服务边界，请使用显式端点。

### 显式 MCP 端点

在 Controller 上添加 `@McpEndpoint`，即可定义独立的 MCP 服务名称、版本和访问路径：

```java title="UserMcpController.java"
import tech.smartboot.feat.ai.mcp.enums.PromptType;
import tech.smartboot.feat.cloud.annotation.Controller;
import tech.smartboot.feat.cloud.annotation.mcp.McpEndpoint;
import tech.smartboot.feat.cloud.annotation.mcp.Param;
import tech.smartboot.feat.cloud.annotation.mcp.Prompt;
import tech.smartboot.feat.cloud.annotation.mcp.Resource;
import tech.smartboot.feat.cloud.annotation.mcp.Tool;

@Controller
@McpEndpoint(
        name = "user-service",
        title = "User Service",
        streamableEndpoint = "/mcp/user"
)
public class UserMcpController {

    @Tool(name = "findUser", description = "根据用户 ID 查询用户")
    public String findUser(
            @Param(required = true, description = "用户 ID") Long userId) {
        return "用户编号：" + userId;
    }

    @Prompt(name = "userSummary", description = "生成用户摘要",
            type = PromptType.TEXT)
    public String userSummary(
            @Param(required = true, description = "用户资料") String profile) {
        return "请根据以下资料生成简洁的用户摘要：" + profile;
    }

    @Resource(
            uri = "docs://user/fields",
            name = "用户字段说明",
            description = "用户资料字段定义",
            mimeType = "text/plain",
            isText = true
    )
    public String userFields() {
        return "id: 用户编号\nname: 用户姓名";
    }
}
```

这个 Controller 暴露一个独立服务，客户端通过 `/mcp/user` 访问。不同的 MCP 能力域可以放在不同 Controller 中，各自使用不同的 `@McpEndpoint`。

`@McpEndpoint` 的能力开关默认开启：Tool、Prompt、Resource 和 Logging。端点路径由必填的 `streamableEndpoint` 指定。

## 三种能力怎么选

| 注解 | 用途 | 典型场景 |
|---|---|---|
| `@Tool` | 执行业务操作或查询 | 查订单、计算价格、创建任务 |
| `@Prompt` | 提供可复用的提示模板 | 代码审查模板、报告生成模板 |
| `@Resource` | 提供可读取的内容 | 规范文档、产品资料、静态说明 |

不要为了使用不同注解而拆分服务。应该先按客户端要完成的任务划分服务边界，再决定一个服务需要哪些能力。

## 参数与返回值限制

注解处理器会在编译期生成参数转换和结果封装代码，因此方法签名需要符合当前生成器支持的类型。

| 能力 | 参数类型 | 返回类型 |
|---|---|---|
| Tool | `String`、基本类型、`Long`、`Boolean` | `String`、基本类型、`ToolResult` 子类，或自定义 Java 类型 |
| Prompt | `String`、`int`、`boolean` | `String` 或 `PromptMessage` |
| Resource | 不接收参数 | `String` |

Tool 返回自定义 Java 类型时，Feat 会将结果序列化为结构化内容。不要直接返回其他 `java.*` 类型（例如 `Map`）；当前生成器不支持这类返回值。异步 Tool 可以返回 `AsyncResponse` 或 `CompletableFuture`。

Prompt 的参数类型比 Tool 更受限；Resource 方法当前只支持无参并返回 `String`。二进制 Resource 也通过 `String` 返回内容，需按注解声明的类型提供对应编码数据。

如果方法签名不符合生成器支持的类型，错误会在编译期暴露，而不是等客户端调用时才发现。

## 什么时候直接使用 McpServer

注解适合编译期就能确定的能力。如果工具列表需要在运行时动态变化，例如来自数据库或插件系统，可以在显式 MCP Controller 中注入 `McpServer`，再使用它的注册 API。

```java
import tech.smartboot.feat.ai.mcp.server.McpServer;
import tech.smartboot.feat.cloud.annotation.Autowired;
import tech.smartboot.feat.cloud.annotation.Controller;
import tech.smartboot.feat.cloud.annotation.PostConstruct;
import tech.smartboot.feat.cloud.annotation.mcp.McpEndpoint;

@Controller
@McpEndpoint(name = "dynamic-tools", title = "Dynamic Tools",
        streamableEndpoint = "/mcp/dynamic")
public class DynamicMcpController {
    @Autowired
    private McpServer mcpServer;

    @PostConstruct
    public void init() {
        // 动态注册时，显式设置端点和启用的能力
        mcpServer.getOptions().setMcpEndpoint("/mcp/dynamic").toolEnable();
        mcpServer.addTool(createTool());
    }
}
```

动态注册时需要在初始化阶段显式设置端点路径，并启用对应能力（`toolEnable()`、`promptsEnable()` 或 `resourceEnable()`），再调用 `addTool`、`addPrompt` 或 `addResource`。注册时机、重复名称处理和动态更新策略由应用负责。

默认情况下，优先使用注解；只有能力集合确实需要运行时变化时，再直接管理 `McpServer`。
