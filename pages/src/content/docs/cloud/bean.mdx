Controller 负责接住 HTTP 请求，但真实业务不会只写在 Controller 里。你通常会把规则、数据库访问、第三方客户端和配置对象拆成不同的 Bean，再由 Feat Cloud 在编译期生成装配代码。

这一章讲的是 Feat Cloud 应用的骨架：哪些对象由容器创建，依赖什么时候注入，初始化和销毁方法在什么阶段执行。

## Bean 声明与注入

先看最常见的三件事：声明 Bean、在 Controller 中注入 Bean、从配置中注入值。

### 声明一个 Bean

把类标记为 `@Bean` 后，Feat Cloud 会在编译期识别它，并在启动时创建实例。

```java title="UserService.java"
import tech.smartboot.feat.cloud.annotation.Bean;

@Bean
public class UserService {

    public String findDisplayName(String username) {
        return "User " + username;
    }
}
```

默认情况下，Bean 名称来自类名首字母小写后的结果。例如 `UserService` 会注册成 `userService`。你也可以显式指定一个稳定名称：

```java title="UserService.java"
@Bean("userService")
public class UserService {
}
```

稳定命名适合跨模块协作，或者你希望启动报错里出现更清楚的业务对象名称。

### 在 Controller 中注入 Bean

`@Autowired` 用在字段上。编译期会生成对应的注入代码，运行时不需要扫描字段注解。

```java title="UserController.java"
import tech.smartboot.feat.cloud.RestResult;
import tech.smartboot.feat.cloud.annotation.Autowired;
import tech.smartboot.feat.cloud.annotation.Controller;
import tech.smartboot.feat.cloud.annotation.PathParam;
import tech.smartboot.feat.cloud.annotation.RequestMapping;

@Controller("users")
public class UserController {

    @Autowired
    private UserService userService;

    // 推荐提供同名、同类型的 setter，让编译期生成代码直接完成注入
    public void setUserService(UserService userService) {
        this.userService = userService;
    }

    @RequestMapping("/:username")
    public RestResult<String> getName(@PathParam("username") String username) {
        return RestResult.ok(userService.findDisplayName(username));
    }
}
```

这段代码表达的结构是：

- Controller 只处理 HTTP 入参和响应
- UserService 承担业务动作
- Feat Cloud 负责在启动阶段把两者接起来

Feat Cloud 按**字段名**查找 Bean，而不是按字段类型查找。例如字段名是 `userService`，容器中就必须存在名为 `userService` 的 Bean；如果类名默认生成的名称不同，可以在类级 `@Bean("...")` 上显式指定名称。找不到时会在启动阶段报错，而不是静默注入 `null`。

注入代码优先调用与字段匹配的 setter（名称为 `setUserService`，参数类型必须与字段类型一致）；没有匹配 setter 时才回退到反射写字段。为了让生成代码保持直接调用，也避免运行时字段反射，建议为需要注入的字段提供 setter。注意，`@Autowired` 注解仍然标在字段上，不标在 setter 方法上。

### 从配置注入值

`@Value` 可以把配置值注入字段。写法上必须使用 `${}` 占位符，配置来自 `feat.yml` 或当前激活环境合并后的配置；还支持 `${key:默认值}` 在配置缺失时提供兜底值。

```yaml title="feat.yml"
app:
  name: demo
  max-users: 100
```

```java title="AppConfig.java"
import tech.smartboot.feat.cloud.annotation.Bean;
import tech.smartboot.feat.cloud.annotation.Value;

@Bean
public class AppConfig {

    @Value("${app.name}")
    private String appName;

    @Value("${app.max-users:50}")
    private int maxUsers;

    public String getAppName() {
        return appName;
    }

    public void setAppName(String appName) {
        this.appName = appName;
    }

    public int getMaxUsers() {
        return maxUsers;
    }

    public void setMaxUsers(int maxUsers) {
        this.maxUsers = maxUsers;
    }
}
```

注意不要省略 `${}`：`@Value("app.name")` 注入的是字面量字符串 `"app.name"`，而不是从配置解析出的值。这里的 `${app.name}` 是读取合并后 `feat.yml` 中的 `app.name` 路径，不是直接用环境变量名查找 `app.name`。如果该配置项的值本身又写成 `${DB_PASSWORD}`，才会在运行时按系统属性 / 环境变量规则解析，详见[启动配置与环境配置](/feat/cloud/options/)。

`@Value` 在实际生成赋值代码时，必须存在字段对应的 setter（名称和参数类型都要匹配），否则编译期会报错。与 `@Autowired` 不同，它不会回退到反射写字段。如果配置项不存在且没有提供默认值，生成器会直接跳过这次赋值，也不会检查 setter，字段保留 Java 默认值。

当前支持的字段类型为 `String`、`int`、`boolean`、`Boolean`、`int[]`、`List<Integer>`、`String[]` 和 `List<String>`；其他类型会在编译期报不支持。

配置参与编译期生成，修改 `feat.yml`、`feat-dev.yml` 或 `feat-prod.yml` 后，需要重新构建应用，生成代码才会更新。

## 生命周期与创建顺序

Bean 进入容器之后，还会经历初始化、依赖顺序和方法级 Bean 创建这些阶段。

### 初始化和销毁

如果 Bean 创建后需要建立连接、预热缓存或检查依赖，可以使用 `@PostConstruct`。应用关闭时需要释放资源，则使用 `@PreDestroy`。

```java title="ClientHolder.java"
import tech.smartboot.feat.cloud.annotation.Bean;
import tech.smartboot.feat.cloud.annotation.PostConstruct;
import tech.smartboot.feat.cloud.annotation.PreDestroy;

@Bean
public class ClientHolder {

    @PostConstruct
    public void init() {
        // 建立连接或检查必要资源
    }

    @PreDestroy
    public void close() {
        // 释放连接、线程池或文件句柄
    }
}
```

生命周期顺序可以简化理解成：

1. 创建 Bean
2. 注入 `@Value`
3. 注入 `@Autowired`
4. 执行 `@PostConstruct`
5. 注册 Controller 路由
6. 应用关闭时执行 `@PreDestroy`

这个顺序决定了一个重要边界：不要在字段声明或构造阶段依赖 `@Autowired` 字段。需要使用依赖对象时，放到业务方法或 `@PostConstruct` 之后。

### 控制创建顺序

`@Bean` 支持 `order` 属性。少数情况下，某个 Bean 必须先于另一个 Bean 准备好，可以显式调整顺序。

```java title="OrderedBean.java"
@Bean(value = "dataSource", order = -10)
public class DataSourceHolder {
}
```

<Aside type="caution">
`order` 是解决启动依赖顺序的工具，不应该成为业务编排手段。大量依赖顺序问题通常说明对象边界需要重新拆分。
</Aside>

### 方法级 Bean

`@Bean` 也可以标在方法上，用来把一个返回对象交给容器管理。方法级 Bean 的名称来自方法名。它适合创建第三方客户端、配置对象或已经封装好的外部资源。

```java title="ClientFactory.java"
import tech.smartboot.feat.cloud.annotation.Bean;

@Bean
public class ClientFactory {

    @Bean
    public PaymentClient paymentClient() {
        return new PaymentClient("https://api.example.com");
    }
}
```

方法级 Bean 会在类级 Bean 创建完成后执行，方法参数按**参数名**从容器中查找对应 Bean；返回对象以方法名注册，例如上例注册为 `paymentClient`。当前实现不会读取方法上 `@Bean` 的 `value` 属性，因此不要依赖 `@Bean("自定义名称")` 为方法级 Bean 改名。

还要注意，方法返回对象只是被注册到容器，并不会像类级 `@Bean` 一样自动生成它自己的字段注入、`@PostConstruct` 或 `@PreDestroy` 处理逻辑。如果对象需要完整的 Feat Cloud 生命周期，优先把它声明为类级 `@Bean`；如果对象必须在 Feat Cloud 容器启动前由外部代码准备好，则可使用 `CloudOptions.registerBean(...)`。
