Feat Cloud 的配置分为三个部分：

| 配置 | 负责什么 | 何时生效 |
|---|---|---|
| `CloudOptions` | 本次应用如何启动 | 启动时 |
| `feat.yml` / `feat-{env}.yml` | 为不同环境生成什么代码 | 编译期 |
| `${...}` | 从 JVM 参数或环境变量注入外部值 | 运行时 |

先记住这条边界：**启动行为用 `CloudOptions`，影响 AOT 生成结果的配置用 `feat.yml`，密码等部署值用 `${...}`。**

## CloudOptions：控制本次启动

`CloudOptions` 继承自 `ServerOptions`。端口、线程数、HTTPS 等基础服务选项仍由 `ServerOptions` 提供；CloudOptions 主要负责服务加载、外部 Bean 和静态资源。

### 限制加载范围

`setPackages(...)` 按生成类的包名前缀筛选本次启动要加载的 `CloudService`：

```java
FeatCloud.cloudServer(options -> {
    options.setPackages("com.example.controller", "com.example.service");
}).listen();
```

它只影响**启动时加载哪些生成类**，不会改变注解处理器的编译范围，也不会减少 AOT 生成代码。匹配使用字符串 `startsWith`，不是严格的 Java 包边界判断，因此包名前缀应尽量明确。

### 注册外部 Bean

数据源、第三方客户端等对象如果已经由应用创建，可以在启动时交给容器：

```java
FeatCloud.cloudServer(options -> {
    options.registerBean("dataSource", dataSource);
}).listen();
```

Bean 名称不能重复，也不能与 Feat Cloud 生成的 Bean 重名，否则启动会失败。

### 配置静态资源

默认静态资源目录为 `classpath:static`。需要更换目录时：

```java
FeatCloud.cloudServer(options -> {
    options.setStaticLocations("classpath:public");
}).listen();
```

也支持文件系统路径，例如 `./public` 或 `/var/www/static`。该方法会创建用于静态资源处理的 Router；如果应用还要自定义 Router，需要留意最终使用的是哪个实例。

## feat.yml：为环境生成代码

Feat Cloud 在编译期读取配置，并为每个 Profile 生成独立的服务类。因此，修改这些配置后需要重新构建，单纯重启已有 JAR 不会更新生成结果。

### 文件约定

默认配置文件：

- `feat.yml` 或 `feat.yaml`

环境配置文件：

- `feat-dev.yml`
- `feat-test.yml`
- `feat-prod.yml`

环境名只允许字母和数字。比如 `dev`、`test`、`prod`；不要使用带横线或下划线的环境名。

`feat.yml` 保存公共配置，环境文件只写差异：

```yaml title="feat.yml"
server:
  port: 8080

feat:
  datasource:
    url: jdbc:mysql://localhost:3306/app
    username: app
    password: ${db.password}
```

```yaml title="feat-prod.yml"
server:
  port: 8081

feat:
  datasource:
    url: jdbc:mysql://prod-db:3306/app
    username: app
```

环境配置会覆盖默认配置：对象按层级合并，普通值和数组整体替换。上例中，生产环境的端口和数据库地址会覆盖默认值，未声明的配置继续沿用默认值。

### server 配置范围

`server:` 并不是对所有 `ServerOptions` 字段开放的通用映射。当前 AOT 通用绑定只处理 `int` 和 `String` 字段；以下特殊项由独立逻辑读取：

| 配置项 | 说明 |
|---|---|
| `port`、`host`、`threadNum` | 监听端口、绑定地址和线程数 |
| `headerLimiter` | 请求头数量上限 |
| `readBufferSize`、`writeBufferSize` | 读写缓冲区大小 |
| `autoSSL` | 自动 HTTPS 开关 |
| `session.store-type`、`session.timeout` | Session 存储方式和超时时间 |
| `gzip`、`gzipThreshold` | 响应压缩开关和阈值 |

特殊项直接读取配置字面值，不支持 `${...}` 占位符。调试模式也不是 `server:` 配置项，应在启动入口调用 `options.debug(true)`。

## ${...}：注入部署环境中的值

占位符用于把密钥等部署值留在运行环境，而不是提交到配置文件：

```yaml
feat:
  datasource:
    username: ${db.username}
    password: ${db.password}
```

运行时按以下顺序查找：

1. JVM 系统属性，例如 `-Ddb.password=secret`
2. 环境变量，名称将点号替换为下划线并转为大写，例如 `DB_PASSWORD`
3. 占位符中的默认值

```bash
java -Ddb.username=app -Ddb.password=secret -jar app.jar

# 或使用环境变量
DB_USERNAME=app DB_PASSWORD=secret java -jar app.jar
```

支持两种写法：

- `${name}`：没有外部值时，字符串结果为 `null`，整数结果为 `0`
- `${name:default}`：没有外部值时使用默认文本

占位符必须占据整个配置值。下面这种嵌入式写法不会解析：

```yaml
# 不会替换
url: jdbc:mysql://${db.host}/app

# 将完整值作为占位符
url: ${db.url}
```

整数类型不要使用带非零默认值的占位符；需要默认整数时，直接在 YAML 中写数字。

`${...}` 不是 YAML 配置项之间的引用。它只读取 JVM 系统属性或环境变量。若要把合并后的 YAML 值注入 Bean 字段，应使用 `@Value`，参见 [Bean 注入](/feat/cloud/bean/)。

占位符只对 Feat Cloud 已接管的配置生效，例如支持的 `server` 字段、数据源和 Redis 配置，以及 `@Value` 使用的配置值。自己通过代码读取的任意 YAML 值不会自动解析。

## 编译与激活 Profile

如果项目包含多个环境配置，AOT 会为每个环境生成一套独立代码，例如：

| 配置文件 | 生成类名 |
|---|---|
| `feat.yml` | `FeatApplication` |
| `feat-dev.yml` | `FeatApplicationDev` |
| `feat-prod.yml` | `FeatApplicationProd` |

运行时通过 `feat.profiles.active` 选择已生成的环境：

```bash
java -Dfeat.profiles.active=prod -jar app.jar

# 或
FEAT_PROFILES_ACTIVE=prod java -jar app.jar
```

JVM 系统属性优先于环境变量。没有指定时使用默认环境；指定的环境名必须与构建时的配置文件一致。若选择了不存在的环境，Feat Cloud 不会自动回退到默认环境，生成的服务可能无法加载。

**Profile 适合表达构建时确定的环境差异**，例如数据库地址、端口和 Session 存储方式。需要运行时动态调整的业务开关，应交给配置中心或业务配置系统，而不是 Profile。
