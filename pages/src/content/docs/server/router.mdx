Router 是 Feat Core 提供的 HTTP 请求分发器。它接收请求 URI，根据注册的路由规则找到对应处理器，再把请求和路径参数交给业务代码。

如果你已经读过[快速开始](/feat/server/)，可以从这一篇开始。这里先关注开发时最常用的 API；匹配算法、拦截器和 Session 的细节分别放在独立章节，避免把使用手册和源码分析混在一起。

## 创建 Router

Router 本身实现了 Feat 的 `HttpHandler`，因此可以直接交给 HTTP Server：

```java title="RouterQuickStart.java"
import tech.smartboot.feat.Feat;
import tech.smartboot.feat.router.Router;

public class RouterQuickStart {
    public static void main(String[] args) {
        Router router = new Router();

        router.route("/", ctx -> ctx.Response.write("Hello Feat"));
        router.route("/users", ctx -> ctx.Response.write("User list"));

        Feat.httpServer()
            .httpHandler(router)
            .listen(8080);
    }
}
```

启动后，访问 `http://localhost:8080/` 和 `http://localhost:8080/users`，会分别进入对应的处理器。

## 注册路由

最常见的注册方式是传入路径和处理逻辑：

```java
router.route("/users", ctx -> {
    ctx.Response.write("User list");
});
```

如果需要区分 HTTP 方法，可以在路径后指定方法：

```java
router.route("/articles", "GET", ctx -> {
    ctx.Response.write("Article list");
});

router.route("/articles", "POST", ctx -> {
    ctx.Response.setHttpStatus(201);
    ctx.Response.write("Article created");
});
```

也可以为同一路径注册多个方法：

```java
router.route("/articles", new String[]{"GET", "POST"}, ctx -> {
    ctx.Response.write("Article endpoint");
});
```

不指定 HTTP 方法的 `route(path, handler)` 会作为该路径的默认处理器；指定方法的注册则只处理对应方法。若路径匹配但 HTTP 方法不匹配，当前实现会转到 Router 的默认处理器；默认情况下它返回 404，而不是自动生成 405。

同一路径、同一 HTTP 方法不能重复注册。重复注册时，Feat 会抛出异常，而不是静默覆盖已有处理器。

## 使用路径参数

路径中有一段内容需要动态变化时，可以使用冒号开头的参数名：

```java
router.route("/users/:id", ctx -> {
    String userId = ctx.pathParam("id");
    ctx.Response.write("User ID: " + userId);
});

router.route("/users/:userId/orders/:orderId", ctx -> {
    String userId = ctx.pathParam("userId");
    String orderId = ctx.pathParam("orderId");
    ctx.Response.write("user=" + userId + ", order=" + orderId);
});
```

例如，请求 `/users/42` 时，`ctx.pathParam("id")` 返回 `42`。参数名来自路由定义，大小写敏感。

Core Router 使用 `:paramName` 语法，不使用花括号形式 `{paramName}`。注意这里讨论的是 Feat Core Router；Feat Cloud Controller 的路径声明语法另见 [Controller 路由](/feat/cloud/controller/)。

## 异步路由处理器

普通的单参数 Lambda 使用的是同步处理方式。如果希望 Router 处理器自己控制异步完成时机，需要实现 `RouterHandler`，并重写带有 `CompletableFuture` 参数的重载方法：

```java
import tech.smartboot.feat.router.Context;
import tech.smartboot.feat.router.RouterHandler;

import java.util.concurrent.CompletableFuture;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.RejectedExecutionException;

ExecutorService executor = Executors.newFixedThreadPool(8);

router.route("/report", new RouterHandler() {
    @Override
    public void handle(Context context) {
        // Router 会调用下面的异步重载；这里是接口要求实现的同步方法。
    }

    @Override
    public void handle(Context context, CompletableFuture<Void> future) {
        try {
            executor.execute(() -> {
                try {
                    String report = loadReport();
                    context.Response.write(report);
                } catch (Exception e) {
                    context.Response.setHttpStatus(500);
                    context.Response.write("Internal error");
                } finally {
                    // 无论业务成功还是失败，都要通知 Feat 请求处理已完成
                    future.complete(null);
                }
            });
        } catch (RejectedExecutionException e) {
            context.Response.setHttpStatus(503);
            context.Response.write("Service unavailable");
            future.complete(null);
        }
    }
});
```

这段代码需要导入 `CompletableFuture`、`ExecutorService`、`Executors`、`RejectedExecutionException`，以及 `RouterHandler` 和 `Context`。线程池应由应用统一管理，并在应用关闭时释放。

异步处理器与同步 Lambda 的关键差别，不在于是否使用了 `CompletableFuture`，而在于谁负责完成请求：同步默认实现会在处理方法返回后自动完成 Future；重写异步重载后，则由业务代码在响应准备完成时调用 `future.complete(null)`。更多线程池和异步生命周期说明见[异步处理](/feat/server/async/)。

## 路径是精确匹配的

Router 不会自动把末尾斜杠视为同一个路径：

```java
router.route("/users", handler);
router.route("/users/", trailingSlashHandler);
```

这两条规则对应不同的 URI。设计 API 时，建议统一路径格式，并在客户端保持一致。

没有任何路由匹配时，默认的 `Router()` 构造器会返回 404。你也可以通过 `new Router(HttpHandler)` 提供自己的默认处理器。

## 接下来读什么

路由规则写出来之后，通常会遇到三个更深入的问题：

- 想知道精确路径、参数、通配符和后缀规则如何参与匹配，继续阅读[Router 匹配过程](/feat/server/router-matching/)。
- 想在请求进入业务处理器前执行鉴权、日志或其他公共逻辑，阅读[Router 拦截器](/feat/server/router-interceptors/)。
- 想在多个请求之间保存登录状态或业务数据，阅读[Router Session](/feat/server/router-session/)。
- 如果处理器需要执行数据库查询或远程调用，再结合[异步处理](/feat/server/async/)了解请求完成机制。
